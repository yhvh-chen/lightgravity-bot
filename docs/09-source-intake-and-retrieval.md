## 1. 目标与范围

目标：用户以最少操作把资料交给 Bot，系统接收原件、形成可追溯的正文与派生、建立可重建的索引，
并让检索结果回到真实原件；整个过程是**受控摄取作业**，不自动创建交付 Task/Run/团队。

资料摄取是**个人 AI 工作助手**定位的一部分：助手把用户资料与目标一起处理，资料先被整理、索引，再用于查找和完成任务；本文只覆盖“整理与查找”这一半，任务执行与验收仍由既有 Task/Run 契约承载。该定位不改变内部编排——摄取是受控、有界、可取消的作业，由程序控制权限与状态，不需要常驻模型编排 agent。方向**待实现、接口未冻结**，不改变首版以开发任务验证交付闭环的范围，也不因定位扩展引入 AIOS、无人值守或外部聊天渠道。

- **范围内（方向已确认）**：Chat 接入入口；原件落盘；提取/OCR/转录；归属识别；正式内容文件；
  文件/元数据/词法优先的索引；可选向量派生；归档、校订、重处理、下载；来源撤销/删除后的失效。
- **范围外（本轮不做）**：通用知识库平台、独立向量数据库服务、多租户、组织协作、邮箱全箱同步、
  自动执行邮件正文里的指令、Office 实测结论、云端/移动端接入。
- **与交付执行的关系**：资料摄取是独立作业，**不自动产生交付 Task/Run**；用户在同一轮里同时要求
  修改工程时，修改部分仍走既有的 Task/Run 与人工验收门（见 §4、[Bot 行为契约](04-bot-behavior.md)）。

## 2. Chat 是唯一常规资料接入入口

- Chat 承担**唯一常规资料接入入口**：支持上传、拖拽，以及粘贴链接。
- 未来从对话发起**文件夹**与**邮箱**接入；必要的选择器/授权页完成选择后**返回同一对话**，
  不另开一个平行业务流程或页面。
- Files 负责预览/浏览/来源追溯/归档调整/校订/重处理/下载，**不要求在多页面重复上传**，
  也**不新增一级知识库入口**。
- 邮箱资料连接器与现有**模型 Connection**（[模型设置](07-settings-and-models.md)、`docs/08` §6.5）
  是不同概念；不把它暗加到已冻结的 Connection/资源 schema 里。
- 全局对话与 Task 对话都可以接资料：Task Chat 中的资料默认归属该 Task；**全局上传不强制建 Task**。

## 3. 接入场景与阶段

| 场景 | 当前定位 | 说明 |
|---|---|---|
| Chat 手动文件 | 先做 | 上传/拖拽；Office 是候选但**未在原型实测** |
| 图片 / PDF | 先做 | 走 OCR/成文后进入词法索引（证据 B 只覆盖合成小样本） |
| 聊天粘贴链接 | 先做（仅记录） | 可先记录链接；**未抓取前不得声称已入库** |
| 中文音频 | ASR 验证通过后接入 | 需服务端具备可用 ASR/音频 mmproj 后才接；否则如实记为失败 |
| 文件夹增量 | 后续 | 从对话发起，返回同一对话 |
| 网页抓取 | 后续 | 未抓取即未入库，不伪造 |
| 邮箱 | 后续 | 选范围接入；**不默认全箱同步，不自动执行邮件指令** |

顺序建议**不含日期承诺**；阶段边界与验收见 §9。2026-10-15 已将资料线正式排入 [LG-033～041](../BACKLOG.md)，任务映射见第 12 节与 [滚动排期 §6](06-roadmap.md#6-去中心化与-embedding-扩展排期2026-10-15)；**仍待实现、接口未冻结**，不声称能力已实现。中文 ASR 先由 [LG-039](../backlog/tasks/LG-039.md) 做质量验证，达标后再由 [LG-041](../backlog/tasks/LG-041.md) 条件接入，且不作为 LG-040 的硬依赖；Office 完整支持、邮箱、文件夹增量与网页正文抓取暂缓，不隐含加排。

## 4. 归属识别与收件区

摄取顺序（方向已确认）：

```text
原件接收 → 先落盘 → 提取/OCR/转录 → 识别归属 → 保存正式文件 → 索引 → 整理归档 → Chat 回执
```

- 原件**先落盘**再处理，避免半成品覆盖来源；落盘位置与命名属于实现细节，未冻结。
- 归属未知的资料进入**受控会话收件区**（attachment/inbox 类受控区域），不直接写进某个 Task/Project。
- 当前 Task/Project **可靠**时沿用其归属；否则先放收件区。
- 全局上传**不强建 Task**；未来 Project 资料共享需要**独立边界**，不与 Task 目录混用。
- 只在**实质歧义**时向用户询问，不把每次上传都变成确认门。
- **模型只做提议**（如建议归属、标签、摘要草案）；授权、归属落定与状态变更由**程序**校验和落实。
- 摄取作业**不自动创建交付 Task/Run/团队**：在资料接入的授权范围内，程序可以直接写原件、
  资料记录、提取件与索引，**不要求工程交付 Run**；这**不等于绕过交付门**——工程源码修改、
  Task 运行控制状态修改等仍遵现有 Task/Run 权限与验收，**摄取不能借机扩大授权**，
  有界工具问答仍只读，也不把每次上传变成重复确认。用户同时要求修改工程则修改部分仍走
  Task/Run 验收；不能把“上传了文件”误解为“开始了交付”。具体处理状态/目录待接口冻结。

## 5. 文件与派生层（事实源）

- **事实源（SoT）**：原件 + 资料 frontmatter/正式内容文件为权威；JSONL 保存历史消息/事件。
- **派生层**：机器提取文本、页图、片段等是**带源版本的派生**；人工校订是**独立版本正式保存**；
  重跑提取**不覆盖**人工校订结果。
- **缓存层**：索引与向量只是可重建缓存，**不存储独有的权限/归属/正文/控制状态**，可整体删除重建。
- **查询回源**：检索先产出**授权候选**，再回源核对存在/哈希/版本/权限，最后定位**真实位置**。
  来源被撤销/删除时，对应命中**失效**，不能返回悬空结果。
- **revision 区分**：内容 **hash**（内容是否变化）与 **stat revision**（文件写入令牌，如
  `size-mtime_ns`）是不同概念，不得互相冒充；`docs/08` §4.3 已明确文件端点的 stat revision
  不是密码学哈希。
- **写入规则**：只做**最小幂等、去重、来源变动/部分成功/并发恢复**规则，不建大平台。
  幂等键、去重键与恢复日志的具体字段未冻结。
- **信任边界**：上传文件的 frontmatter **不能自动成为受信 Task/资源配置或指令**；
  它只是资料元数据，须经程序 schema 校验，未知字段保留但不获得执行语义。

## 6. 处理与检索生命周期

- **处理阶段（设计示意，非现有 Task phase）**：
  `received（已接收）→ processing（处理中）→ extracted（已成文）→ attributed（已归属）→
  indexed（可检索）→ archived（已归档）`；分支为 `partial`、`failed`。这些是**摄取作业/文件**层面的
  展示状态示意，**不加入现有 Task `phase` 枚举**，也不改 `docs/08` §6.1。
- **有界作业**：处理使用**程序编排的有界作业 + 按需模型调用**，限定预算、支持取消与有限重试；
  **不需要常驻编排 agent**。
- **OCR 渲染尺度（可选配置，默认不变）**：PDF 页在 OCR 前由产品光栅化器渲染。PDF 用户单位为 1/72 英寸，
  历史默认渲染 `scale=2.0`（约 144 DPI，注释写作“~150 DPI”）；该尺度为可选质量/组合参数，可通过既有
  环境配置入口（`LIGHTGRAVITY_OCR_SCALE`）显式覆盖并真正传到产品处理与光栅化路径（非仅独立后端测试）。
  缺省/空值保持默认 2.0 不变；非法值（非有限、非正数、超过已记录安全上限）**显式报错，不静默夹取为通过**；
  现有页数/输入/内存上限不受影响。该参数为**加性、非秘密**配置，不改变 API/schema/端点，不改变默认行为。
- **OCR 可选表格模式（可选配置，默认关闭）**：新增可选、默认关闭的 `LIGHTGRAVITY_OCR_TABLE_MODE`。
  接受值仅为不区分大小写的开/关（开 `1`/`true`/`yes`/`on`，关 `0`/`false`/`no`/`off`），其它值**显式报错**。
  开启时由**程序侧、模型无关、有界**的版面分类器先判断页面是否确有**横线 + 多列一致 gutter** 的真实表格网格，
  **仅**对该页使用显式 Markdown 表格提示词；普通页（清晰/印刷/扫描/非 PNG）**始终用未改动的默认提示词**，
  默认行为与逐字节请求不变。分类只看像素与几何（不含文件名/哈希/页码/真值），常量比率为固定记录值、非逐页调参。
  判定记录（`prompt_kind`/`prompt_sha256`/`table_classification`）只写入不透明派生证据
  （`derivative/ocr_evidence.jsonl` 与 pages 派生文档），不进入冻结的公开实体/API 字段；
  页数与输入上界沿用既有处理边界，无新增无界输入路径。该模式属**实现说明增补（无契约版本变化）**，
  不改变 API/schema/端点，未配置时不改变任何默认行为。
- **Job 只是逻辑设计**：它描述一次摄取/提取/索引作业的边界，**不新建第二套业务状态库**；
  权威状态仍落在文件（原件 + frontmatter/内容文件 + JSONL），可重建视图由索引承担。
- **作业与交付分离**：摄取作业与被 `docs/08` 冻结的 Run/Subtask/Member 是不同层面；
  不因为一次上传而占执行槽或排队交付。
- **失败诚实**：失败**不造空的成功正文**；**失败说明不作为知识正文参与检索**（避免把报错当资料）；
  原件与历史事件保留，用户可重试或换方式。
- **Chat 回执**：按**每个文件**明确 `已收到 / 处理中 / 成功 / 部分成功 / 失败`，并给出
  来源、产物位置、是否可检索，以及失败原因。Files 读取**同一份**文件状态，不另建状态。

## 7. 索引与检索边界

- **优先级**：文件、元数据、**词法**检索优先；embedding 是**可选派生**，不是前提。
- **不要求独立向量库服务**：`vectors.npy` / `items.json` 之类只是**参考实现**，**未冻结**；
  首版不需要单独的向量数据库服务。
- **媒体可直接向量检索**：媒体可直接做 embedding 检索，**不强制先转文字**；OCR/ASR 成文是
  **另一条通路**（成文后可走词法/正文检索）。
- **三者能力不同**：文本 embedding、多模态 embedding、OCR/ASR 的**能力、模型与预算不同**，
  不能把向量当作文字，也不能用一条通路的结论推断另一条。
- **词法与向量的分工**：词法负责精确命中（编号、金额、日期）；向量负责语义近似（受阈值与余量约束）；
  两者都只产候选，最终**回源核对**（§5）。

## 8. 幂等、去重与失败恢复（最小规则）

- **幂等**：同一上传/链接/来源的重复提交按**稳定接入请求 ID**返回首次结果，不重复建资料、
  不重复跑模型；幂等绑定请求 ID，而不是“同一 URL 永远跳过”，因此相同 URL 的合法重试仍可更新来源。
  同一请求 ID 若 payload 不同，按**冲突**处理并如实回执，不静默接受或覆盖（规则设计，字段未冻结）。
- **去重（作用域内）**：按**来源 + 内容 hash** 识别**同一来源、同一授权范围**内的重复提交；
  同一内容不同名不重复建权威记录。
- **跨来源/跨 Task 不合并**：相同字节来自**不同来源**或**不同 Task/Project** 时，保留各自的
  来源记录、作用域、权限与引用；即便未来共享底层 blob，也不得自动合并授权、抹掉来源或扩大可见范围。
- **来源变动**：来源内容 hash 变化时生成**新的源版本**并重建其派生/索引/向量，旧版本对应命中失效；
  重跑不覆盖人工校订版本。
- **部分成功**：多文件/多页处理允许部分成功；回执如实区分成功与失败，不把失败伪装成成功。
- **并发恢复**：写用原子替换 + 版本检查；进程中断后先检查已落盘原件与不完整的派生/索引，
  不静默重放副作用不明的处理。
- **授权**：检索只返回调用者被授权的候选；权限不存储于索引/向量，读取时回源核对。

## 9. 分阶段与验收

阶段划分参考证据范围；**无日期承诺**。每项验收必须在实现冻结接口后由真实证据支撑，
不以文档或原型脚本视为通过。

| 阶段 | 内容 | 建议验收（未实现前不得声称通过） |
|---|---|---|
| P1 | Chat 手动文件 + 图片/PDF 成文 + 词法索引 | 上传→落盘→OCR→归属→正式文件→词法检索→回源命中；失败/部分成功如实回执；来源变化后旧命中失效 |
| P2 | Office 候选 | 在原型中实测后才定义范围；未测前只标候选 |
| P3 | 中文音频 | 服务端具备可用 ASR/音频 mmproj 并通过已知转写验证后才接入；否则保持失败记录 |
| P4 | 文件夹增量 / 网页抓取 | 从对话发起并返回同一对话；未抓取不得声称已入库 |
| P5 | 邮箱 | 选范围接入；不默认全箱同步、不自动执行邮件指令 |

不要把 P1 的合成小样本结论外推为生产质量；不要把某一阶段的通过写成后续阶段已通过。

**语言政策（当前范围，2026-10-16 用户市场范围决定）**：资料线的集中验收（[LG-040](../backlog/tasks/LG-040.md)）**以英文为主线**——英文正文/表格/图片/查询/UI/错误流与词法/向量降级；版本 PASS 前须先覆盖完整英文质量/端到端。中文以当前水平支持、抽样回归、限制照实披露，**中文图片排名 7 本身不再单独阻断英文导向版本的 QA**（旧中文图片硬门 FAIL 作为历史质量结果保留，不重算、不调阈值）。**安全/数据丢失/权限/假成功无论语言始终阻断。** 这是**前瞻性范围/接受决定，非追溯实验通过**，**不表示英文 E2E 已证明**，也**不解除 P3 中文音频的锁**：**英文市场不等同支持英文 ASR**，**不假装转写已存在**。

## 10. 实测与局限

本节只引用已有证据，链接见 [probes/source-intake/README.md](../probes/source-intake/README.md)；
LAN 端点只作**一次性只读探针目标**记录，**不是运行默认或产品依赖**。原始报告未改写。

- **证据 A（EG2 端点探针）**：单次只读探针目标是 **llama.cpp `llama-server` router
  `b11641-843e7dcc1`**（非 Ollama）；目标地址仅记录在 [证据入口](../probes/source-intake/README.md)，
  **不是运行默认或产品依赖**。`embeddinggemma-2-Q8_0` 返回 **768 维**、有限、L2=1.0；

  渲染页），NFKC 去空白后 76/87 字符、**CER 0**、字段精确命中；首请求含自动加载 **162.247 s**，

  `/v1/audio/transcriptions` → 501、`input_audio` → 500；**`gemma4-mtp` 未测**、**无 reader 接线证据**，
  不能断言全服务无 ASR。索引侧：精确词/负对照、删缓存重建 hash 不变、改副本来源拒过期命中。
  单 batch5 向量语义排序**余量 0.048**，**非质量结论**。
- **范围澄清**：**已测 Qwen 的中文截图/扫描页 OCR 成功**；**已测 Qwen 的 ASR 路由
  （`/v1/audio/transcriptions` 501、chat `input_audio` 500）拒绝**；**已测 embedding 模型转写失败**；
  **`gemma4-mtp`/其它生成模型与 reader 未测**。因此**不能断言整台服务均无 ASR**。
- **环境局限**：原型运行在**系统 Python 3.14 + 临时脚本**，**不是**产品 `Python 3.12` 依赖验收，
  也不是 Antigravity adapter/后端接入；探针与产品代码不互相 import。
- 未测：Office、多页/混合版式 PDF、真实/多样中文样本、生产级 OCR/检索质量、邮箱与抓取。
