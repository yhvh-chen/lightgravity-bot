# LG-013 — 接入 Task Chat 与真实看板

## 目标

支持网页创建/继续任务、查询、交付审阅与验收。

## 范围

阶段：左侧五入口。仅实施本项所需首版能力；不扩展多后端、组织、云端或外部渠道。

## 验收条件

- 全局/Task 历史、附件、消息与范围一致。
- 看板读真实 phase，控制 pending 与实际结果分开，失败不伪装运行中。
- 从任务卡可审阅产物并验收，错误可恢复，浏览器实际路径留证。

## 依赖

LG-010、LG-011、LG-012 为接口或实际交付需要，不是单纯阶段排序。

## 验证记录

实施完成并本包验收通过（真实 API 接线 + 必要局部证据）；真实浏览器 HTTP 业务路径尚未通过，归入版本验收门 LG-021/022，不在本小任务重复执行全浏览器 QA。

状态分层说明：

- **本包实施验收（已通过）**：任务范围内真实 API 接线、服务层真实 HTTP 联调、定向测试与前端局部证据均已完成，无已知业务代码未实现或断路。据此置为 done。
- **版本 QA（待执行，归 LG-021/022）**：真实浏览器 HTTP 端到端业务路径、交付审阅/真实验收停止释放、以及直答模块在配置真实协调器连接后的真实模型一次调用，均留作版本验收门集中覆盖。
- **真实模型能力**：普通直接模型回答需先配置协调连接；本包未新增实测，不将 unavailable/mock 或 LG-010 的既有真实闭环当作本任务真 AI 能力证明。（**整合期补充**：已在配置真实默认协调连接后补做 1 次直答探针并通过，见下文“整合期新增”；仍不覆盖交付/组队路径。）

本轮在 `dev/lg013` worktree 复原并补跑检查。自动化与真实 HTTP 层通过；真实浏览器 HTTP 路径在本机 headless Chrome 不可用，如实记录（见限制），未以构建成功替代该证据，改由 LG-021/022 版本 QA 覆盖。

- 本轮真实 HTTP 联调（真 uvicorn + `lightgravity start`，port 8803，自建进程组、仅自清理）：`GET/POST /conversations/global/messages` 往返、交付请求创建真实 Task（`queued`）、`GET /tasks` 读真实 phase（无 worker 连接时显示 `failed`，未伪装运行中）、`GET /tasks/{id}`/`events`/`artifacts`、普通问题分类 `direct` 且 `creates_task:false`、任务数不变。原始输出见下文。

- 真实模型：本轮未新增模型调用。可直接复用的真实执行证据来自 LG-010：`probes/lg010/evidence/lg010-evidence*.json`（真实 DeepSeek 闭环）。本任务普通只读直答路径未做真实模型一次调用（见限制 3），未把 unavailable/mock 当作真实 AI 回答。

### 限制

1. **真实浏览器 HTTP E2E 尚未通过（保留为本版本验收项，归 LG-021/022）**：本机 `google-chrome --headless=new` 无法访问 loopback HTTP（`--dump-dom http://127.0.0.1:PORT/` 30s 超时，服务端无 `GET /`）；导航 host 问题已有独立 root probes/browser-diagnostics 诊断。`lg013-live-e2e.mjs` 因此未能在真实 HTTP 上取得浏览器证据；未以文件级检查冒充。此项不删除、不伪称通过，集中到版本 QA 门 LG-021/022 执行。**整合期更正**：root `probes/browser-diagnostics` 已推翻旧“全 HTTP/fetch 阻断”结论——真实 loopback HTTP 的 `fetch`/SSE 从 `file://`/`about:blank` shell 可用，真正失败的只是**顶层 `Page.navigate` 到 `http://`**；本项限制的实质是“顶层导航不可用”，非“HTTP 整体不可用”。
2. 真实浏览器证据仅覆盖 `file://` inline build 的空态/范围保持/单会话；含后端的历史、创建、验收路径由服务层真实 HTTP（上文）覆盖。
3. 直答模块 `backend/lightgravity/coordinator/dialogue.py` 在**未配置默认协调器连接**时返回诚实 unavailable；真实模型直答需配置连接后由版本 QA 覆盖。
4. 交付审阅/验收的真实停止释放端到端证据依赖 worker 连接；本轮 harness 未配置真实连接，验收路径仅在服务层读取侧验证。

### 整合期新增：真实模型只读直答探针（1 次）

整合执行者在本整合 worktree 补做了 **1 次** 有界真实模型探针（非版本 QA），证明新直答路径在真实默认协调连接下可用且边界收敛：

- 脚本 `probes/lg013/scripts/lg013_direct_answer_probe.py`，证据 `probes/lg013/evidence/lg013-direct-answer-probe.json`，说明 `probes/lg013/README.md`；凭证仅来自进程环境（不读 `.env`、不打印/落盘秘密）。
- 结果：HTTP 200，`kind=direct`、`data.intent=answer`、`data.creates_task=false`，**真实模型回答 `"Four."`**（非内置 fallback/`unavailable` 文本）。
- 边界核对：`created_tasks=0`、`created_members=0`、`created_runs=0`，workspace 文件清单为空，`leak_findings=[]`——直答不创建 Task/Run/Member、不写控制文件、工具/Workspace 无写入。
- 计量诚实：该探针硬上限 1 次模型调用（`model_calls_cap=1`）；产品未暴露调用计数器，故**实际次数以“本次探针 1 次”为准，不宣称精确总量**。它只答一个短问题，不覆盖交付/组队路径（仍属 LG-010/021/022）。

### 开发中修正（非产品故障）

- `lg013-live-e2e.mjs` 原在 attach 后 `Page.navigate`，观察其结果不回返导致 harness 挂起（即历史 SIGTERM 期间所处阶段）。已改为 `Target.createTarget({url})` 且 `CdpClient.send` 增加 15s 有界超时；该修正仅针对测试 harness 健壮性，不改变产品行为。
- 更早的 SIGTERM(143) 与 EDQUOT 均为执行环境中断/配额，非产品缺陷；dirty 源码/测试/证据保留未重置。
