## 范围

**2026-10-16 LG-022 独立复验 R1（非实施者 owner，`qa/lg022-r1`，主代理只 PM）**：候选 `ec2420e`
（= 整合候选 `9698e8a` 产品树，契约 `1.9.0`；含 R1 返修 `fix/lg022-r1` @ `d07a4a6`）。

- 判定：**FAIL（未达成功门，保持 `in-progress`）**。真实主链在真实 DeepSeek 下执行到 `phase=verifying` 后
  **未到 `awaiting_acceptance`**，`POST accept` 返回 `409 illegal_transition "task phase 'verifying' has no pending acceptance decision"`。
- 根因（产品缺陷，经本地确定性复现定位，非测试等待窗口）：成功 Run 落盘 `session_refs` 非空但 `cleanup.status="pending"`；
  `verify/stopgate.py::StoreResourceStopper` 要求 `not session_refs or cleanup=="done"`，而**正常成功路径从不把
  `cleanup` 写成 `done`**（`done` 只在 stale run、recovery_required、人工 accept 后写入）→ `verify_and_prepare` 恒 `unconfirmed` →
  验收门对任何真实 session-bearing Run 死锁。最小复现：`probes/lg022/reverify-r1/harness/stopgate_repro.py`
  （`deadlock_reproduced: true`，控制组 `no_sessions`/`cleanup_done` 均可正常放行）。
- 第二缺陷（计量硬门）：`GenerationCounter` 仅进程内内存，**跨重启不持久**（`counting-proof.json` C4
  `persisted_across_restart: false`），不满足 PLAN 的“跨 service/进程重启不归零”。
- 真实成功项：真实 worker 写产物、Settings 默认 pin、reviewer 装配 `model`、reviewing 期间状态查询不阻塞
  （`max 1.313s`）、D3 成功 Run 无伪 `fail_reason`。
- 预算：本 phase 真实生成请求 **6/10**（`remaining=4`，精确计数）；旧 phase real 调用 **unknown**（单列，未 reset）；
  本续接收尾 **0** 真实请求（仅本地确定性探针）。
- 证据：`probes/lg022/reverify-r1/REPORT.md`、`STATUS.md`、`evidence/`（`real-chain.json`、`counting-proof.json`、
  `stopgate-repro.json`、`deterministic-probe.json`、`dry-run.json`）、`harness/`。
- 需返修（交主代理另派，QA 不自修）：① `verify/stopgate.py` + 成功 Run 的 session 停止/`cleanup=done` 生命周期；
  ② `adapter/proxy.py::GenerationCounter` 跨重启持久化。修复后须由新的独立 QA 复验。
