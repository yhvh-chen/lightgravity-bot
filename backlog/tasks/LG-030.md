# LG-030 — 实现受控同伴交接与上下文传递

## 目标

让 worker 根据实际需要请求协作和交接成果，消息及权限仍经程序管控。

## 范围

去中心化协作版本。本次仅排期，未启动实施。无外部聊天渠道、多租户、全邮箱同步或自主触发。

## 验收条件

- 同伴发现、请求、响应有 task/run/node、消息 ID 与因果关联；重复、越权、过期消息有明确结果。
- 只传递获准摘要及带版本/哈希的产物引用；拒绝跨 Task 泄漏、失效来源和把来源正文当控制指令。
- 协作请求受总预算、次数、超时和容量控制，等待同伴不得形成无限循环；交接失败可诊断并恢复。

## 依赖

LG-028、LG-029 为接口或集成交付依赖。

### 集成 owner 复核与兼容修复（2026-10-16，batch3 集成）

- **核验结论**：030 协议在受保护 HTTP（loopback + 必要时 `X-LG-Token`）与真实 `FileStore` 路径上
  实现了冻结的 `POST/GET /runs/{id}/collab_requests`，默认关闭（`collab_requests_enabled=false`），
  幂等、因果绑定、同 Run 成员校验、跨 Task/Run 拒绝、带 sha256/`evidence:` 的产物引用、
  预算/次数/超时/容量门、注入正文不执行——这些验收项有真实 FileStore+HTTP 测试与新的默认 app 协议链复现。
- **真实缺口（集成 owner 最小兼容修复）**：此前端点身份取自请求体 `from_member_ref`，与契约
  “worker 侧调用须经受控执行身份，不接受浏览器直接指定任意 owner”不符。已加**程序认证依赖接缝**
  `ApiContext.worker_identity`（`(Request) -> str | None`）并在 `PeerService.request` 要求
  `authenticated_member_ref` 与 body 一致；**未接缝或身份不符时默认拒绝**（`unauthenticated`/`identity_mismatch`，
  **不落盘**）。**body 自报身份永不作为认证**。真实 worker 身份注入（协调器注入已认证 Member）归 **LG-031**，
  不阻塞本项：本项交付的是**安全的协议边界**，默认关闭且默认拒绝。
- **本地检查（真实退出码）**：`uv run pytest tests/collaboration -q` → **57 passed**；
  真实默认 app 协议链 `uv run python probes/lg030/http_protocol_check.py` →
  `DENY rejected unauthenticated` / `POST 200 requested True` / `REPLAY True` / `BUDGET rejected budget_exhausted` /
  `GET 200 ['c1','c2']`（`probes/lg030/http_protocol_check.out`）。
- **仍未做（归 LG-031，不是本项 blocker）**：真实受控执行身份注入、Graph 运行时接线
  （`LeaseManager`/`PeerService` 进协调器图）；完整 checkpoint skip（对齐 docs/08 §6.2）。
- **状态**：协议本身安全满足 → `done`（待版本 QA LG-032）；不再因“待 031 运行时接线”人为延长 in-progress。
