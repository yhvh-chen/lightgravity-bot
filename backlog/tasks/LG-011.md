# LG-011 — 实现左侧导航与统一前端壳层

## 目标

实现 design.md 的视觉 tokens、共享组件与多栏壳。

## 范围

阶段：基础与探针。仅实施本项所需首版能力；不扩展多后端、组织、云端或外部渠道。

## 验收条件

- 五工作入口位于左侧、底部另有 Settings 齿轮，顶栏仅范围、面板控制和通知；设置页面具体接线由 LG-026 完成。
- 切换保留 Task/Run/选中项/草稿，无重复 Chat/session。
- 键盘、焦点、窄屏和错误/空态有浏览器依据，模拟数据明确标记。

## 依赖

LG-001、LG-002 为接口或实际交付需要，不是单纯阶段排序。

## 交付内容

- `frontend/src/app/`：壳层与路由。`AppShell`、`TopBar`、`NavigationRail`、`ShellProvider`、`uiState`（URL/会话偏好）、`navigation`、`layoutMock`、`useMediaQuery`、`tokens.css`、`shell.css`。
- `frontend/src/components/`：共享组件层 `ContextList`、`SplitPane`（`PanelResizer`）、`StatusBadge`/`MockBadge`、`TaskCard`、`ResourceCard`、`DetailHeader`、`MarkdownViewer`、`ChatComposer`、`ChatPanel`、`EmptyState`、`ErrorState`、`NotificationList`、`icons`。
- `frontend/src/api/`：`types`（对齐 docs/08 错误信封/health/version/枚举）、`client`（真实 `/api/v1` fetch + 错误信封）、`useBackendStatus`（真实 `/health` 探测）。
- `frontend/src/views/`：独立视图入口 `registry.tsx`；`ChatView`（单 Chat 实例）与 Board/Files/Team/Resources/Settings 占位（各自 owner 任务扩展）。
- `frontend/tests/`：`shell.test.tsx`、`components.test.tsx`、`setup.ts`，以及无依赖的浏览器检查 `tests/browser/shell-check.mjs` 与 `tests/browser/inline-build.mjs`。

失败与处理（均为环境/检查脚本问题，非应用缺陷）：

1. DevTools `Page.navigate` 在 `http://127.0.0.1` 上挂起，且 Chrome 在该沙箱无法加载任意 http(s)（`--dump-dom` 对 localhost 与外网均为空），而 `data:`/`file:` 正常。改为用 `Target.createTarget` 直接打开页面，并提供 `inline-build.mjs` 把产物内联为自包含 HTML 以走 `file://`。
2. 首轮浏览器检查 22/23：脚本在 Chat 视图错误断言 `.lg-chat--rail` 存在（该视图应为 `.lg-chat--main`）。修正断言后 23/23。

限制与未验证项：

- 未启动后端（未 `uv sync`/uvicorn）；浏览器中 Chat 显示真实的 “Backend not connected”（`/health` fetch 失败，`network_error`）。连接成功路径的空态由 vitest 以真实 `HealthResponse` 形状的 fetch stub 覆盖，未做真实后端联调。
- 业务端点（Task/Run/Messages/SSE/Files/Resources/Settings）未实现，页面按要求显示占位/空态/未接入，不假功能；真实数据路径待各视图任务与版本 QA。
- 键盘/焦点/窄屏仅在上述 Chrome 无头环境验证；真实触摸、屏幕阅读器、`prefers-reduced-motion` 仅做了 CSS 处理，未实测。
- 截图在 `/tmp`，不随仓库保存；版本 QA 或整合环境如可访问 loopback HTTP，可直接用 `vite preview` + `SHELL_URL` 运行同一脚本。
- `npm audit` 仍报 6 个告警（3 moderate / 1 high / 2 critical），来自 LG-002 锁定版本，本任务未改动依赖。

需整合 owner（串行）处理的事项：

- 本任务未改任何共享文件：`frontend/package.json`、`frontend/package-lock.json`、`frontend/vite.config.ts`、`frontend/tsconfig.json`、`frontend/index.html`、后端与文档/契约均未触碰；未新增前端依赖。
- `frontend/src/views/registry.tsx`、`frontend/src/app/navigation.ts`（`ownerTask` 标注）与 `frontend/src/api/` 后续会被 LG-013/014/015/026 扩展。虽然 docs/08 将 `frontend/src/**` 归 LG-011，但这些文件被多个视图任务共享，建议由整合 owner 串行接线或按任务明确临时 owner，避免并发改同一文件。
- 既有 `frontend/README.md` 仍描述 LG-002 边界；整合 owner 可补充 LG-011 后的目录说明（本任务不在授权写入路径内）。
