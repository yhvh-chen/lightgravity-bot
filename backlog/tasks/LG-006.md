# LG-006 — 实现 Antigravity Executor Adapter

## 目标

实现 Subtask 执行、事件、结果、取消和关闭。

## 范围

阶段：最小真实闭环。仅实施本项所需首版能力；不扩展多后端、组织、云端或外部渠道。首版唯一真实路径为 `google-antigravity==0.1.22` + `LocalOpenAIAgentConfig`（`openai-compat`）+ loopback 认证代理接 DeepSeek；不新增 SDK 或通用多厂商平台。

## 验收条件

- 返回实际产物、diff、结构化 outcome、session 和可取得用量。
- cancel/close 有真实运行证据，不把取消请求当成停止结果。
- 工具失败/预算停止/正常完成分类有效，worker 不写控制状态。
- 产品侧 loopback 认证代理作为 executor 组件实现：只监听 loopback，明确定义启动/停止/失败生命周期，停止需确认并清理残留代理/worker 进程，凭证只从 env 或受控 secret store 引用（`credential_ref`）解析且不落日志/事件/响应。
- 不复制或依赖 LG-003 探针、参考仓库或开发机路径；adapter 不把“config built”当作认证成功。
- 记录实际发送给 SDK 的 model ID 与 `base_url`；首选 `deepseek-v4-flash`，LG-003 探针当时使用的是 `deepseek-chat`。

## 依赖

LG-003、LG-005 为接口或实际交付需要，不是单纯阶段排序。

### 给 LG-007 / LG-025 的稳定接口

- `AntigravityExecutor` 实现 `ExecutorAdapter`：`execute(request, emit) -> ExecutorResult`、`cancel(execution_ref) -> CancelResult`、`close(session_ref)`、`capabilities()`。
- `ExecuteRequest`：docs/08 §8 字段 + adapter 扩展 `agent_ref`（指向 LG-005 `agent` 资源）、`save_dir`、`conversation_id`、`response_schema`。LG-007 负责构造并持久化；`execute` 只 `emit(dict)`，不写控制状态。
- `ExecutorResult`：`state`、`summary`、`artifact_refs`、`diff_ref`、`diff`、`check_records`、`session_ref`、`failure`、`usage`、`stop_reason`、`stop_confirmed`、`model`/`upstream_model`。
- LG-025 通过 `CredentialResolver` 注入受控 secret store；默认 `EnvCredentialResolver` 支持 `credential_ref`→env（如 `deepseek-api-key`→`DEEPSEEK_API_KEY`）。代理上游 allowlist 固定；新增上游属契约/安全变更。
- `cancel` 仅在确认 SDK 会话 idle 后返回 `confirmed=true`；`stop_confirmed=false` 时不得写终止状态。
