# LG-023 — 完成单 agent 对照评估

## 目标

评估组队相对单 agent 的真实交付收益。

## 范围

阶段：首版验收。仅实施本项所需首版能力；不扩展多后端、组织、云端或外部渠道。

## 验收条件

- 固定任务输入、版本、资源约束和验收条件。
- 比较完成率、时间、可取得成本与人工修正，缺失数据标未知。
- 可复现且说明样本局限和不适合组队场景，不用角色数量代替收益。

## 依赖

LG-022 为接口或实际交付需要，不是单纯阶段排序。

- **设计**：2 小型真实代码样本（S1 独立两文件修复、S2 跨模块依赖交接）× 2 arm（A 单实施 worker / B 组队两 worker 带 hash 交接）× 1 次；两 arm
  **共用**相同机器门（fixture 验收）、同一独立 `ModelReviewer`、同一版本验收门、同一 SDK/模型/权限/预算；`single worker` **不含** reviewer，不以 agent 数量代替收益。
- **预算（采样前冻结，全 stage 同一持久 ledger）**：总 **48** / 每 attempt **12**；output ≤16000 / HTTP 120s / retry 0 / 并发 ≤2。
- **离线门（先于真实请求，全过）**：fixtures 初始必败、reference 必过（6/6）；ledger L1–L7（硬上限 48、第 49 次拒绝、跨实例/跨进程持久、损坏 fail-closed 绝不当 0、attempt 上限 12、全 stage 同一账本）；
  两 arm 冻结合法 plan 过真实 `PlanValidator`；attempt guard 拒绝第 13 次。证据 `probes/lg023/evidence/offline/`。
- **真实结果（PARTIAL，全部失败/bring-up 保留）**：**S1×A 在最终 harness 下真实交付候选**——真实 SDK worker 自主认领 `deliver`、覆盖两文件，
  **共用机器门 6/6 全过**、**独立 `ModelReviewer` `passed` + `validate_findings` 通过**；真实生成 **6**（worker ~5 + reviewer 1），elapsed 15.11s。
  **版本验收门未闭合**：`verify_and_prepare` 返回 `unconfirmed`（`cleanup='pending'`，1 session 未确认关闭），**未降门/未伪造 `done`**。
  S1×B、S2×A、S2×B 仅在 bring-up/旧 prompt 下运行（`dispatcher=failed`，`MAX_TOOL_CALLS_EXCEEDED`）；**预算耗尽未在最终协议下重跑**，**不算组队结论**。
- **计数**：本 phase 真实生成 **45/48**（bring-up 5 + 首次四 attempt ~23 + S1/A 修正 17），剩 3；**usage/费用部分 `unknown`，不当 0**；未完成样本不计交付。
  旧 LG-022（unknown+6+8+5/10）与 LG-031（34/40）**单列不并入本 48、不洗 0**。
- **人工干预/开发成本**：修 harness 字段 bug、加 `edit-file`、收紧 worker 提示、接入真实停止门端口；pi dispatch token/time 未逐样本分摊，记 `shared`。
- **结论（限定，不夸大）**：**不支持任何“组队相对单 worker 的 token/成本收益”结论**（样本 1、费用 unknown、prompt confound、组队 arm 未取得最终协议数据）；
  可核实的是**单 worker 能在本 harness 完成一个小型两文件交付并过机器门+独立复核**。**组队 arm 待新预算 phase 在相同最终 prompt/门 下重跑**。
- **限制**：强制冻结合法 plan 拆分（非产品自动规划能力对照）；旧/新提示混用；版本验收停止门未闭合（两 arm 相同）；未覆盖浏览器/恢复/取消/长会话。
- **证据**：`probes/lg023/{PLAN,STATUS,REPORT}.md`、`evidence/`、`runs/`、`ledger/`、`harness/`。**未推送/部署/发布**。
