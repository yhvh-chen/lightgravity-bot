# LG-007 — 实现常驻消息路由与 Task 队列

## 目标

实现轻问答、交付工作、查询和控制请求的统一入口。

## 范围

阶段：最小真实闭环。仅实施本项所需首版能力；不扩展多后端、组织、云端或外部渠道。

## 验收条件

- 普通问答不组队，文件修改关联 Task/Run，新交付有目标与验收。
- 全局/Task 消息按 messageId 持久去重，不重复创建执行。
- 单执行槽、队列依赖、执行中查询与歧义目标处理有验证，worker 不随网页请求结束。

## 依赖

LG-004、LG-006 为接口或实际交付需要，不是单纯阶段排序。

状态：实现完成，满足自身验收条件；**待版本 QA**（由 LG-010/021/022/027 覆盖真后端与整合验收）。

### 限制与诚实说明

- 所有执行证据使用 in-process `FakeExecutor`（mock），**仅单元证据**；真实 SDK/DeepSeek 端到端由 LG-010 验证，本任务不宣称已真实验证。
- 未持久化 adapter 流式事件（`adapter.text`/`tool_call` 等），仅记录 `adapter.error`。Run 详情事件由 LG-016/LG-014 扩展。
- Run `attempt` 暂固定为 1；重试/返修尝试编号由 LG-016 负责。
- 暂停在非 `executing` 阶段受限并如实返回 `not_pausable`；完整暂停/取消/恢复语义由 LG-016 负责。
- 控制动作 `request_id` 幂等在异步路径为 lookup+record，极端并发下可能重复调用一次（本身幂等/无副作用）；创建 Task 使用加锁的同步 `execute`，并发安全。
- 未在真实 `bot-data`、未启动 uvicorn、未 push、未 deploy。
