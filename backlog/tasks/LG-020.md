# LG-020 — 实现启动检查与本地分发入口

## 目标

提供单用户本地启动、诊断和停止清理。

## 范围

阶段：恢复与质量。仅实施本项所需首版能力；不扩展多后端、组织、云端或外部渠道。

## 验收条件

- 缺认证/runtime/资源时仍可读历史且明确执行不可用；缺模型时可进入 Settings 配置、测试并设置默认，再恢复执行入口。
- 默认 loopback，秘密不进聊天，持久目录和进程生命周期明确。
- 干净环境可复现启动/停止，版本锁定与许可说明齐备，不包含云端发布。

## 依赖

LG-006、LG-011、LG-012、LG-026 为接口或实际交付需要，不是单纯阶段排序。

### 验收对照

- 单命令启动/停止、loopback 默认、端口/数据/workspace/secret/dist 隔离：`start`/`stop`/`status` 真实子进程往返通过。
- 缺认证/runtime 时历史与 Settings 可读、执行明确不可用：`GET /tasks`、`GET /settings` 200；`execution_report` 给出具体 `reasons`，缺 key 返回 `capability_unavailable`，不崩溃也不造假。
- 模型未配置 → Settings 保存/测试/设默认 → 恢复执行：init 后 `execution_ready=false`（缺凭证），写入受控 store 凭证后 `execution_ready=true`、`agent_refs=["developer"]`、`reasons=[]`；Connection 文件只含 `credential_ref`。
- 默认 loopback + 敏感写默认拒绝：无 token 的 `PATCH /settings` → 401 `unauthorized`，带进程内 token 成功；Host/Origin 守卫只放行 loopback/显式允许值。
- 首次启动握手：`index.html` 响应注入内存 `window.__LG_RUNTIME_TOKEN__`（带 `no-store`），不写 URL/日志/持久存储；前端 `auth.ts`/`settings.ts` 调用时读取该全局，无需改前端源码。
- 幂等初始化：第二次 `lg init` 全部 `skipped`，revision 不变；已有用户资源不被覆盖。
