# LG-012 — 实现查询 API 与持久事件订阅

## 目标

向网页提供只读投影、受控操作与事件流。

## 范围

阶段：最小真实闭环。仅实施本项所需首版能力；不扩展多后端、组织、云端或外部渠道。

## 验收条件

- 读 Task/Run/Member/资源/文件，遵冻结 API，错误与冲突明确。
- 事件持久后广播，游标重放和去重有效，断线不结束任务。
- 路径与凭证边界有效，网页不能直接改控制文件。

## 依赖

LG-004、LG-007 为接口或实际交付需要，不是单纯阶段排序。

## 实现记录

执行者 `agent:pi-lg012`，独立 worktree `dev/lg012`。仅新增/修改本任务 owner 路径：`backend/lightgravity/api/**`、`tests/api/**`、本任务文件。未改 `contracts`、`store`、`adapter`、`coordinator`、`settings`、根依赖、README/PROJECT/docs/frontend，也未改其它 worktree。未读取 `.env`，未打印任何凭证值。

### 产物（`backend/lightgravity/api/`）

- `app.py`：真实装配 `FileStore`(LG-004) → `BroadcastingStore` → `Coordinator`(LG-007)；`ConnectionService`+`FileSecretStore`(LG-025) 复用 `Settings.secret_store`；lifespan `start()/stop()` 常驻 Coordinator；挂载 health/coordinator/tasks/resources/files/events/settings 全部 `/api/v1` 路由；全局 `require_access` 依赖 + `AppError` 处理器（含 `ETag`）。提供 `store`/`coordinator`/`dispatcher`/`executor`/`connection_service`/`access_policy`/`tester` 注入点：LG-008 注入图 Dispatcher，LG-006/LG-010 注入 `AntigravityExecutor`，均不改本文件。
- `access.py`：`AccessPolicy` 协议 + 默认 `LocalAccessPolicy`；凭证/设置写接口（`/api/v1/settings` 的 POST/PUT/PATCH/DELETE）在未注入授权机制时**默认 401 拒绝**，非 loopback 请求一律要求 `X-LG-Token`；LG-020 注入真实启动授权后可放行。
- `eventbus.py`：`EventBroker`（进程内 pub/sub，慢订阅者关闭后由客户端凭游标重放）+ `BroadcastingStore`（先持久化到 JSONL 再广播，非第二事实源）+ `v1:<stream_id>:<seq>` 游标解析/SSE 编码。
- `tasks.py`：`GET /tasks`（phase/status/archived + `limit`/`cursor`）、`GET /tasks/{id}`（含 active Run/Subtask/Member 投影 + `ETag`）、`PATCH /tasks/{id}`（`expected_revision`，标题/范围/验收；需求字段变更 `requirements_revision+1` 并重置 acceptance）、`GET /tasks/{id}/events`（`after_seq`/游标）、`POST /tasks/{id}/actions`（pause/cancel 经 Coordinator 落盘并区分 confirmed/unconfirmed；未实现动作诚实返回 `not_ready` 并标注 owner）。
- `resources.py`：`GET /resources/{kind}`、`GET /resources/{kind}/{id}`，覆盖七类资源 + Connections；经 Store 读取，跳过坏文件，不复制第二份配置。
- `files.py`：`GET /files`、`GET /files/content`，经 `Store.resolve_path` 限制在授权根内；拒绝 `..` 与逃逸符号链接（`path_outside_workspace`）；二进制 base64、大文件截断、只读。
- `events.py`：`GET /events/stream` SSE；先订阅 broker 再按游标重放，按 `(stream_id, seq)` 去重，支持 `Last-Event-ID`；心跳保持；断线只取消该生成器。
- `health.py`：`/health` 能力位按真实装配动态上报（store/coordinator/events_sse/settings/files/resources；`sdk_adapter` 仅在注入了真实 executor 时为 true）。
- `tests/api/**`：`conftest.py`/`api_helpers.py` 及 `test_tasks.py`、`test_events.py`、`test_resources_files.py`、`test_settings_integration.py`、`test_access.py`、`test_lifespan.py`。

### 限制与诚实说明

- 本记录是执行者局部证据，**待版本 QA**（LG-021/022 覆盖真实浏览器与端到端）；不代表版本验收通过。
- SSE 回放/断线用进程内 ASGI 驱动（`AsgiEventStream`）验证，未通过真实 uvicorn 网络栈；httpx `ASGITransport` 会缓冲响应，故未用它测流式。
- 真实 SDK/DeepSeek 端到端仍属 LG-010：本地测试使用 `UnavailableExecutor` 或 in-process `FakeExecutor`/`StubDispatcher`，仅为单元/接线证据。
- `GET /events/stream` 无游标时只推送订阅后的新事件；跨多个 stream 的全局回放需要每个 stream 的游标，首版未引入全局序号。
- Run/Member 目前通过 `GET /tasks/{id}` 的 `run`/`members`/`subtasks` 投影读取；未新增未冻结的 `/runs/{id}`、`/members/{id}` 端点。
- 全局 Chat（`Coordinator.submit_global_message`/`read_global_messages`）已有服务方法，但契约未定义 HTTP 端点，本任务未暴露。
- 完整暂停/取消恢复、验收动作语义由 LG-016/LG-009 负责，此处仅接线到 Coordinator 的稳定控制入口并以 `not_ready` 诚实拒绝其余动作。
- 基线 `tests/adapter/test_executor_canned.py::test_executor_confirms_cancel_mid_stream` 为既有时序性 flaky（在改动前已存在；重复单跑通过）。
