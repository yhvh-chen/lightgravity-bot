# LG-015 — 实现 Team 与 Resources 管理视图

## 目标

展示待招募模板、已招募成员及七类资源。

## 范围

阶段：左侧五入口。仅实施本项所需首版能力；不扩展多后端、组织、云端或外部渠道。

## 验收条件

- Team 状态与实际一致，已释放不计当前成员但历史可查。
- Resources 七分类有引用导航，Session Profiles 与真实会话分开；Connections 编辑关联 Settings 的同一 Connection，不维护第二份配置。
- 资源健康未知/禁用/缺依赖可区分，模板修改走受控对话且不影响运行实例。

## 依赖

LG-005、LG-008、LG-011、LG-012 为接口或实际交付需要，不是单纯阶段排序。

## 实现记录

### 产物

- `backend/lightgravity/resources/__init__.py`、`service.py`（新目录，LG-015 独占）：`ResourceService` 在 LG-004 Store 上提供目录读取、诊断（declared / parsed / dependencies / runtime availability 分离）、引用入/出导航、`/team` 视图所需的 agent 模板与 Member 实例读取，以及**窄口径受控写入**（非 connection 资源的 allow-list 字段，先按 adapter schema 重解析、再解析全部引用，最后经 `Store.write(expected_revision=...)` 原子写入）。不 import SDK、不 eval、不读 secret 值；connection 明确拒绝并指向 Settings。
- `backend/lightgravity/api/resources.py`（扩展）：保留 `GET /resources/{kind}`、`GET /resources/{kind}/{id}`（新增 availability/diagnostics/references/inbound_refs），新增 `PATCH /resources/{kind}/{id}`（写前 `ctx.access.authorize(request, sensitive=True)`，复用 LG-012 `AccessPolicy`/运行时 token，不绕过默认拒绝）、`GET /team/available`、`GET /team/members`。
- `backend/lightgravity/coordinator/resource_commands.py`（本轮新增，LG-015）：**结构化、有界**资源修改提议的校验契约（`{kind, id, expected_revision, patch, body}`）。不做自然语言解析、不调用额外模型；只接受 `role=user`，字段 allow-list/schema/引用/revision 校验仍由 `ResourceService.update` 完成。
- `backend/lightgravity/coordinator/service.py`、`api.py`、`__init__.py`（最小 hook）：Task 消息可携带加性 `resource_proposal`，`Coordinator.submit_task_message` 在持久化消息后同步校验并调用 `ResourceService.update`，把实际结果/冲突写回同一 Task 对话（assistant 消息带 `resource_result.status`）。该路径不创建 Run、不排队等待代码 worker；`POST /tasks/{id}/messages` 在带提议时执行与 PATCH 相同的 sensitive 授权。
- `tests/resources/{conftest.py,test_resources.py}`：9 项真实 `create_app` + tmp 数据目录测试。
- `tests/resources/test_resource_proposals.py`（本轮新增）：10 项受控提议测试（applied/幂等/冲突/引用拒绝/非 user 拒绝/connection 转 Settings/畸形提议/Task 404/默认拒绝 token/活跃成员配置不热替换）。
- `frontend/src/api/resources.ts`、`api/team.ts`：对齐后端形状的客户端；PATCH 与 `proposeResourceChange` 携带内存 token。
- `frontend/src/views/resources/{ResourcesView.tsx,availability.ts,Diagnostics.tsx,resources.css,contextRail.tsx}`：七分类列表/详情、字段、引用（出/入）、Markdown 正文、诊断；Session Profiles 明确标注为配置模板而非活跃对话；Connections 详情跳 Settings 并携带具体 connection id；非 connection 资源通过 **Task 对话受控提议** 修改（无 Task 时只引导，不假写）。
- `frontend/src/views/team/{TeamView.tsx,returnState.ts,team.css,contextRail.tsx}`：Available 读 agent 模板并展示编译可用性；Recruited 读 Member 实例，当前队伍排除 released、released 历史可展开；成员固定配置版本/`skillRefs` 导航；“Request for current task” 仅写入 Task Chat 草稿并跳转，不直接创建 worker。
- `frontend/src/views/registry.tsx`、`frontend/src/app/AppShell.tsx`（最小接线）：Team/Resources 二级资源栏改为数据驱动的 `Context` 组件（真实 Available/Recruited 与七类分类选中），不再渲染 mock 组织/数据；Files/Chat/Board/Settings 入口保持原样；Settings 主区由小型 `SettingsRoute` 读 `settings:connection:<id>` 并传给 `SettingsView`。
- `frontend/src/views/settings/SettingsView.tsx`（加性 id 定位接口）：新增可选 `connectionId`/`taskRef` props；按 id 选中具体 Connection，保留 Task 范围展示。未改后端实体。
- `frontend/src/views/{TeamView.tsx,ResourcesView.tsx}`：仍为薄 re-export，registry 既有 `./TeamView`/`./ResourcesView` 入口不变。
- `frontend/tests/{team.test.tsx,resources.test.tsx,settings.test.tsx}`：jsdom 组件测试（含受控提议、无 Task 引导、Settings id 定位、Team 数据驱动资源栏）。

### 受控对话修改的真实链路（本轮完成项 1）

`ResourcesView` 的 Controlled change → `proposeResourceChange` → `POST /api/v1/tasks/{id}/messages`（`role=user` + 加性 `resource_proposal`）→ 协调器 `parse_resource_proposal`（结构/角色）→ `ResourceService.update`（allow-list + adapter schema + 引用 + `expected_revision`）→ `Store.write` 原子写 → 实际结果/冲突作为 assistant 回复写回同一 Task 对话。无有效 Task 返回 404；非 user / 无 sensitive 授权明确拒绝；消息按 `message_id` 幂等；活跃 Member 的 `config_hash`/状态不变（模板只影响后续招募）；该处理不创建 Run、不等待代码 worker。

### Connections 定位（本轮完成项 2）

`Edit in Settings` 写入 `settings:connection:<id>` 选择引用并跳转；`SettingsRoute` 解析后传给 `SettingsView.connectionId`，在连接列表按 id 选中同一条记录。Task/run 范围由 shell 保留（`setView` 不清空 taskRef），Settings 头部展示当前 task。纯 UI 定位，无后端实体字段。

### 资源栏真实数据（本轮完成项 3）

`VIEW_DEFINITIONS` 新增可选 `Context` 组件；`AppShell` 在存在时用它替换静态 `buildContext`。
`TeamContextRail` 调 `GET /team/available` + `GET /team/members`（当前 + released 历史），`ResourcesContextRail` 渲染七类分类并高亮当前类别/详情对应类别。已移除 `MOCK_AVAILABLE_ROLES`/`MOCK_RECRUITED_MEMBERS` 的展示。整体布局、单 Chat、草稿、Files/Settings 入口未改。
