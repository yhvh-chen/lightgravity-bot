# LG-015 — 实现 Team 与 Resources 管理视图

## 目标

展示待招募模板、已招募成员及七类资源。

## 范围

阶段：左侧五入口。仅实施本项所需首版能力；不扩展多后端、组织、云端或外部渠道。

## 验收条件

- Team 状态与实际一致，已释放不计当前成员但历史可查。
- Resources 七分类有引用导航，Session Profiles 与真实会话分开；Connections 编辑关联 Settings 的同一 Connection，不维护第二份配置。
- 资源健康未知/禁用/缺依赖可区分，模板修改走受控对话且不影响运行实例。

## 依赖

LG-005、LG-008、LG-011、LG-012 为接口或实际交付需要，不是单纯阶段排序。

## 实现记录

### 产物

- `backend/lightgravity/resources/__init__.py`、`service.py`（新目录，LG-015 独占）：`ResourceService` 在 LG-004 Store 上提供目录读取、诊断（declared / parsed / dependencies / runtime availability 分离）、引用入/出导航、`/team` 视图所需的 agent 模板与 Member 实例读取，以及**窄口径受控写入**（非 connection 资源的 allow-list 字段，先按 adapter schema 重解析、再解析全部引用，最后经 `Store.write(expected_revision=...)` 原子写入）。不 import SDK、不 eval、不读 secret 值；connection 明确拒绝并指向 Settings。
- `backend/lightgravity/api/resources.py`（扩展）：保留 `GET /resources/{kind}`、`GET /resources/{kind}/{id}`（新增 availability/diagnostics/references/inbound_refs），新增 `PATCH /resources/{kind}/{id}`（写前 `ctx.access.authorize(request, sensitive=True)`，复用 LG-012 `AccessPolicy`/运行时 token，不绕过默认拒绝）、`GET /team/available`、`GET /team/members`。
- `tests/resources/{conftest.py,test_resources.py}`：9 项真实 `create_app` + tmp 数据目录测试。
- `frontend/src/api/resources.ts`、`api/team.ts`：对齐后端形状的客户端；PATCH 携带内存 token。
- `frontend/src/views/resources/{ResourcesView.tsx,availability.ts,Diagnostics.tsx,resources.css}`：七分类列表/详情、字段、引用（出/入）、Markdown 正文、诊断；Session Profiles 明确标注为配置模板而非活跃对话；Connections 详情只跳 Settings，不复制模型列表；非 connection 资源提供受控修改（title/enabled/body，写 revision、显示冲突/拒绝）。
- `frontend/src/views/team/{TeamView.tsx,returnState.ts,team.css}`：Available 读 agent 模板并展示编译可用性；Recruited 读 Member 实例，当前队伍排除 released、released 历史可展开；成员固定配置版本/`skillRefs` 导航；“Request for current task” 仅写入 Task Chat 草稿并跳转，不直接创建 worker。
- `frontend/src/views/{TeamView.tsx,ResourcesView.tsx}`：改为薄 re-export，registry 既有 `./TeamView`/`./ResourcesView` 入口不变（视图已进入主构建）。
- `frontend/tests/{team.test.tsx,resources.test.tsx}`：16 项 jsdom 组件测试。

### 真实 API 临时目录冒烟（不提交脚本，`fastapi.testclient` + tmp data dir + 注入 token）

- `GET /resources/agent` → 200，availability `unknown`（declared+parsed，未做真实健康检查）；`GET /resources/agent/developer` → 200（references 解析、inbound_refs）；`GET /team/available` → 200；`GET /resources/trigger/nightly` → 200 且 availability `unsupported`（未启动）。
- `PATCH /resources/agent/developer` 无 token → **401 `unauthorized`**（默认拒绝，复用 `AccessPolicy`）；带 token → **200**（revision 0→1，ETag `"1"`）；过期 revision → **409 `revision_conflict`**；`PATCH /resources/connection/deepseek` → **400 `invalid_request`**（提示改用 Settings，同一 Connection 权威）；未 allow-list 字段 → **400**。

### 限制与未做

- **验收条目“模板修改走受控对话”未完成**：本轮交付的是程序校验 + Store 原子写 revision 的受控写入（`PATCH /resources/...`），但没有把 Task 对话消息路由为资源修改提议——协调器不在本任务 owner 范围。按用户指令**不置 done**，列为 blocked/待接线（见下）。受控写入已保证：只写资源配置、不 import/eval、不扩大权限；活跃 Member 保持其 pin 的 `config_hash`，模板修改只影响后续招募。
- Connections “编辑跳 Settings”只到 Settings 页面，尚不能定位到具体 Connection 记录（SettingsView 无选择入参，属 LG-026/LG-011 共享壳接线）。
- Team/Resources 的**资源栏二级导航仍由 LG-011 registry 静态/含 mock**渲染；本任务在视图主区实现了真实分类/列表与选择，但未改共享 `views/registry.tsx`。
- 资源健康为**如实 unknown**（未连接 MCP/Trigger/real session 的健康检查）；未做浏览器可视化/E2E，均留 LG-021/LG-022 版本 QA。
- 新增 `GET /team/available`、`GET /team/members`、`PATCH /resources/{kind}/{id}` 为加性只读/受控端点，docs/08 §4.3 尚未登记，交整合 owner 处理契约 MINOR。
