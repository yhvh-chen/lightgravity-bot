# LG-035 — 接入图片和 PDF OCR 与正式内容版本

## 目标

把图片与 PDF 转成有来源关系、可校订的 Markdown。

## 范围

资料接入与 Embedding 版本；LG-041 为后续中文转写扩展。本次仅排期，未启动实施。无外部聊天渠道、多租户、全邮箱同步或自主触发。

## 验收条件

- 使用授权模型后端验证实际产品环境，记录模型/端点/配置；两份合成探针不足以替代产品验收。
- 覆盖真实清晰页、低质量页、多页、混合文本/扫描页与表格，预先固定真值和质量判据；页码及原件引用可追溯。
- 原始机器输出与人工校订版本分离，重处理不覆盖正式校订；失败与部分成功不冒充知识正文。

## 依赖

LG-034 为接口或集成交付依赖。

## 验证记录

实施已启动并落盘；**未置 done**：真实中文样本/表格质量门阻塞，且集中 QA 归 LG-040。

### 本包交付（2026-10-16，基点 `61fad69`）

- 新增 `backend/lightgravity/sources/ocr/**`（`adapter.py` 可配置 OpenAI-compatible
  真实 HTTP OCR；`pdf.py` 基于 pypdfium2 的 PDF 逐页栅格化，仅用标准库编码 PNG）、
  `sources/content.py`（机器派生 vs 人工正式版本，分目录、重处理不覆盖）、
  `sources/processing.py`（逐页有界、部分失败/取消/超时诚实）、`sources/service.py`
  与本包唯一 owner 的 `api/sources.py`（`/content`、`/download`、`/actions`、`/formal`）。
- 依赖：`pyproject.toml` + `uv.lock` 新增 `pypdfium2>=5,<6`（BSD-3-Clause +
  Apache-2.0，均宽松许可；自包含 wheel，无系统 poppler；按需懒加载）。未引入 Pillow。
- 配置：`LIGHTGRAVITY_OCR_BASE_URL` / `LIGHTGRAVITY_OCR_MODEL` 等环境变量，**不硬编码 LAN**；
  未配置时诚实地 `capability_unavailable`，保留原件。
- 证据：`probes/lg035/QUALITY-PLAN.md`（调用前预注册阈值与样本）、`STATUS.md`、
  `INTEGRATION.md`、`REPORT.md`、`reports/**`（脱敏原始响应、HTTP 日志、统计）。
