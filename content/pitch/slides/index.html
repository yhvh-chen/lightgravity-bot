From multimodal source intake to verified delivery in six deterministic steps.

§ 04 — Layer 1: Human Team Collaboration

One team bot. Shared across people, accountable by role.

Multi-account collaboration designed for real small teams, not a solitary chatbot tab.

1. Personal vs. Team Workspaces

Individual user accounts with admin and member roles. Personal provides private chat and owner-only attachment analysis; Team provides shared group chat, source intake, and task tracking.

2. Silent Group Context + Explicit @bot

Teammates converse freely in group chat without AI interrupting. Messages are saved silently as shared context; an explicit @bot command invokes the assistant only when requested.

3. Verified Cross-Account Delivery Flow

Teammate A creates the task and binds sources ➔ AI Team executes and passes independent review ➔ Teammate B downloads deliverable, inspects it, and submits feedback ➔ Teammate A accepts on Board.

§ 05 — Layer 2: Task-Scoped AI Teams

275 specialist roles. Governed by code, not prompts.

Autonomous teams assembled on-demand, strictly bound by permissions, budgets, and independent review.

GATE I

Goal-Based Recruitment & Scope

Packages 282 upstream agency templates; 275 specialist roles are recruitable with our toolset via deterministic goal-fit ranking. Each task runs with an ephemeral team in an isolated workspace. Role descriptions never expand file/tool permissions.

GATE II

Author ≠ Reviewer Separation

Workers returning success enter verification—they cannot self-grade done. Acceptance mandatorily requires an independent Reviewer model connection checking artifacts against criteria and bound sources.

GATE III

Budgets & Confirmed Stop

Budgets span execution, verification, repair loops, and failed attempts. Task pause, cancellation, or completion requires confirmation that runtime execution has actually stopped before terminating states are persisted.

Appendix A — Task Ontology Schema & lakeFS Integration

Task Ontology: Explicit schemas & zero-copy lakeFS branches.

How TASK.md YAML frontmatter and lakeFS branch-merge architecture scale the File SoT model.

TASK.MD AUTHORITATIVE SCHEMA
---
title: "Quarterly Analysis & Delivery"
task_id: "01M5XYZ..."
revision: 3
requirements_revision: 2
sources:
  - ref: "sources/source_01ABC"
    hash: "sha256:7f8e..."
team:
  coordinator: "deepseek-chat"
  workers: ["data-analyst", "tech-writer"]
  reviewer: "gemini-1.5-pro"
status: "pending_review"
acceptance_criteria:
  - "Evidence artifacts pass schema validation"
  - "Independent Reviewer verdict is PASS"
---
GCS + LAKEFS DATA LAKE TOPOLOGY

Zero-Copy Branch per Task: When Task Run starts, a virtual branch run/01M5XYZ is branched off main instantly at metadata cost.

Atomic Merge on Acceptance: Workers commit artifacts to the branch. Once independent Reviewer passes and human clicks Accept on Board, lakeFS executes an atomic merge back into main.

Zero data duplication · Reversible audit trail · Multi-instance safe
